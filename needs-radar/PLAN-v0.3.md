# 需求雷达 v0.3 改造方案：从「每日帖子流」到「已验证的需求库」

状态：待确认 · 2026-11-04

## 0. 目标

找到**真实存在、还有市场**的需求，用来做网站赚钱。两条变现线都要：

- **流量线**：SEO 流量 + 广告 / 联盟（看搜索量、首页弱度）
- **付费线**：工具直接收费（看 CPC、付费意愿、付费竞品是否活着）

改造的核心原则：**Reddit 等讨论负责「发现」，关键词数据负责「证明」**。LLM 只做理解和判断可建性，不再凭印象给需求和竞争打分。

## 1. 新流水线

```
① 抓取     Reddit 定向版块(按领域配额) / 句式搜索 / HN Ask / (二期) 差评、自动补全
② 粗筛     时效 + 去重 + 自荐帖过滤 + 每领域保底名额
③ LLM 提炼  痛点卡 + 3–5 个英文种子关键词 + 付费意愿原文 + 受众类型(B2C/B2B)
④ 关键词扩展 Google 自动补全扩长尾（免费）
⑤ 关键词量化 DataForSEO：月搜索量 / CPC / 竞争度 / 12 月趋势（一天 1 个批量任务）
⑥ 首页分析  DataForSEO SERP：首页 10 条分类 → 论坛/UGC、文章、专门工具、大站/官方
⑦ 聚类入库  新卡片归入已有「机会」或新建一个；证据持续累积
⑧ 评分     流量线分 / 付费线分（公式算，数据驱动）+ LLM 只给可建性和差异化角度
⑨ 输出     日报：系统健康 + 新机会/证据变强的机会（≤5 条）
           周报：两条线各 Top 3 + 关键词表 + vibecoding prompt + 手动复核清单
```

## 2. 数据模型（seen.db 新增）

| 表 | 关键字段 | 用途 |
|---|---|---|
| `opportunities` | id, title, summary, audience_type, status, first_seen, last_seen, evidence_count, distinct_subs, traffic_score, paid_score, buildable, angle | **机会库主表**，一个痛点一行 |
| `evidence` | opp_id, item_id, url, sub, date, quote, pay_signal | 每个帖子作为一条证据挂到机会上 |
| `keywords` | keyword, volume, cpc, competition, trend_json, fetched_at | 关键词指标缓存，30 天内不重复查 |
| `opp_keywords` | opp_id, keyword, source(llm/autocomplete) | 机会 ↔ 关键词 |
| `serp_snapshots` | keyword, date, n_ugc, n_article, n_tool, n_big, top_json | 首页结构快照 |
| `runs` | date, 各源抓取数/报错数, 搜索与 LLM 调用数, 费用估算 | 健康监控与成本追踪 |

`status` 取值：`new → watching → validating → building → shipped / rejected`。
原 `pains` 表保留，只读，用于回灌历史。

## 3. 评分（公式 + 少量 LLM）

所有分数 0–100，公式参数放 `config.yaml` 可调。

**需求证据分**（两条线共用）
- 搜索量：机会下所有关键词月搜索量之和，取对数归一（100/月 ≈ 低，10k/月 ≈ 高）
- 讨论证据：出现次数、不同版块数、时间跨度（反复出现 = 慢性痛）
- 趋势：近 3 月 vs 前 9 月搜索量

**流量线分** = 需求证据 × 首页弱度 × 可建性
- 首页弱度 = 首页里论坛/UGC/薄内容占比；有大站或官方工具占位则扣分
- 长尾加分：自动补全扩出的同族词越多，越适合批量生成页面

**付费线分** = 需求证据 × 商业价值 × 可建性
- 商业价值：CPC（广告主愿意出的价 = 钱在流动）、B2B/专业人群加分、原文出现付费意愿（"I'd pay"、提到价格或在用的付费工具）
- **有付费竞品不扣分**，记为「市场已验证」；只有竞品又多又强、首页没有弱点时才扣分

**LLM 只负责**：可建性（1–3 天能否做出 MVP）、差异化角度（一句话）、毒舌点评。
解析失败时标记为「评分失败」，**不再默认 3/3/3**。日报设最低分门槛，宁缺毋滥。

## 5. 历史回灌（第一个能立刻用上的产出）

已有 662 张卡片（7-29 至今），一次性处理：

1. 聚类成机会库（预计会合并成一两百个机会）
2. 给每个机会的关键词批量查搜索量 / CPC（几千个词也只要几个批量任务）
3. 对排名靠前的机会做首页分析

产出：**「过去 4 个月的需求排行榜」**，按两条线各排一份。你不用等新数据跑起来，就能先从里面挑点子。

以上单价来自官网和第三方页面，以注册时官网为准。代码里按 `runs` 表统计每日用量，并设每日预算上限。

## 7. 需要你确认的决策

1. **仓库改成私有吗？**（推荐）现在每天的需求日报和你的 👍/👎 都是公开的，等于把选题公开给所有人。私有仓库的 Actions 免费额度每月 2000 分钟，现在每天约 8 分钟，够用。
2. **邮件节奏**：推荐「日报精简（≤5 条 + 健康段）+ 周日周报（决策用）」；也可以只要周报。
3. **Reddit OAuth**：推荐配（免费，5 分钟），能解决 429，也能拿到赞数和评论数。
4. **DataForSEO**：需要你注册并充值，然后把 `DATAFORSEO_LOGIN` / `DATAFORSEO_PASSWORD` 加到仓库 Secrets。
